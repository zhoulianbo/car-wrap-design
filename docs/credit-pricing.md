# 积分包与支付商品配置

价格及到账积分以 `src/config/pricing.ts` 为准，所有商品均为一次性付款，积分永不过期。

| 站内商品 ID        | 价格（USD） | 到账积分 | 展示位置                       |
| ------------------ | ----------- | -------- | ------------------------------ |
| `credits_100`      | $4.99       | 100      | 价格页、普通积分付费墙         |
| `credits_250`      | $9.99       | 250      | 价格页、普通积分付费墙         |
| `credits_1000`     | $29.99      | 1000     | 价格页、普通积分付费墙         |
| `credits_trial_20` | $2.00       | 20       | 符合条件的未付费用户体验付费墙 |

## Waffo / Creem 上线配置

Waffo 后台的 Webhook 通知地址为 `https://carwrapdesign.app/api/payment/notify/waffo`（POST）。其他部署域名替换域名即可，不添加语言前缀。`/api/payment/callback` 是结账后浏览器跳转地址，由系统自动生成，不填写为 Webhook 地址。

这两个支付渠道使用平台商品 ID。修改站内价格目录不会自动创建或更新支付平台上的商品；Waffo 创建结账时传入商品 ID 和币种，由平台商品决定实际收款价格。

1. 在所使用的支付平台创建或核对上表四个 USD 一次性商品及价格。
2. 在 `/admin/settings` 对应渠道的商品映射中，将四个站内商品 ID 映射到平台实际商品 ID：Waffo 使用 `waffo_product_ids_mapping`，Creem 使用 `creem_product_ids_mapping`。
3. 核对支付回调配置，并在沙箱中验证收款金额、到账积分、`user.is_paid` 和重复回调行为。站内自动化测试采用模拟支付回调，不代表平台真实支付已验证。

## 数据迁移与体验优惠

上线前需备份并审核应用 `scripts/migrations/20261010-user-paid.sql`（SQLite / D1）；其他数据库按对应 schema 生成迁移。成功付费用户获得 50 MiB 附件额度，未付费用户保留 5 MiB。

体验优惠的次数、两小时截止时间和关闭标记仅存于当前浏览器的 localStorage，按账号隔离。清理浏览器数据或更换设备不会保留这些行为记录。数据库只保存成功付费标记，不保存优惠行为。

触发次数在 `src/config/pricing.ts` 的 `trialOfferConfig` 中配置：`closeThreshold` 控制普通付费墙关闭次数，`purchaseClickThreshold` 控制购买按钮点击次数。任意一项达到阈值后，在用户关闭普通积分付费墙时展示体验包。

关闭体验包仅隐藏本次弹窗；首次触发后的两小时内，未付费用户再次关闭普通积分付费墙时可重新看到体验包。倒计时始终沿用首次截止时间，不因关闭、刷新或再次展示而延长；过期后不再展示。
